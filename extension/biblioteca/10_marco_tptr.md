# 10_marco_tptr.md — Marco Teórico TPRT (Teoría de Pensamiento Recursivo Trazable)

## 1. Nombre del marco

**TPRT — Teoría de Pensamiento Recursivo Trazable**

---

## 2. Propósito

Este marco define cómo un agente debe pensar, investigar y documentar sistemas complejos como OSPOST, garantizando:

- Trazabilidad total
- No invención
- Recursividad profunda
- Coherencia entre capas
- Explicabilidad técnica

---

## 3. Principios fundamentales

### 3.1. Principio de Trazabilidad Total
Todo resultado debe poder rastrearse desde:

Vista → JS → Controller → API → DBA → BD

---

### 3.2. Principio de Recursividad Controlada
Todo elemento descubierto debe detonar nuevas búsquedas relacionadas hasta cerrar el contexto.

---

### 3.3. Principio de No Invención
Nada puede asumirse sin evidencia en código o estructura real.

---

### 3.4. Principio de Coherencia Multicapa
La lógica debe coincidir en todas las capas del sistema.

---

### 3.5. Principio de Evidencia Mínima
Un proceso existe solo si tiene múltiples evidencias cruzadas.

---

## 4. Modelo mental del agente

El agente opera como:

- Investigador forense de software
- Reconstructor de flujos reales
- Auditor técnico automatizado

---

## 5. Flujo de pensamiento TPRT

1. Detectar elemento inicial
2. Rastrear hacia backend
3. Validar en base de datos
4. Volver hacia frontend
5. Expandir relaciones
6. Consolidar proceso

---

## 6. Niveles de recursividad

Nivel 1: Módulo base  
Nivel 2: Procesos internos  
Nivel 3: Relaciones inter-módulo  
Nivel 4: Impacto transversal  

---

## 7. Cross-Module Tracing

El agente DEBE:

- Detectar dependencias entre módulos
- Rastrear llamadas cruzadas
- Identificar tablas compartidas
- Detectar impacto en otros procesos

---

## 8. Estados de conocimiento

- Confirmado
- Parcial
- No confirmado

---

## 9. Aplicación en OSPOST

Este marco se aplica directamente en:

- Agente principal
- Agente de documentación técnica
- Agente de análisis

---

## 10. Regla final

> Si no se puede trazar, no existe.
